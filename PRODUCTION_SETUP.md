# Pherall — Production Setup Guide

This document covers everything required to deploy Pherall to Vercel with a production PostgreSQL database.

---

## Prerequisites

- A Vercel account
- A PostgreSQL database (Neon, Supabase, Railway, or any managed Postgres)
- A Resend account (for transactional email)
- A Stripe account (for payments — can be configured later)
- A domain name (optional but recommended)

---

## 1. Environment Variables

Set the following in your Vercel project dashboard under **Settings → Environment Variables**.

| Variable | Required | Description |
|---|---|---|
| `DATABASE_URL` | **Yes** | PostgreSQL connection string (pooled for serverless) |
| `AUTH_SECRET` | **Yes** | Random secret for Auth.js JWTs — generate with `openssl rand -base64 32` |
| `NEXTAUTH_URL` | **Yes** | Your full production URL, e.g. `https://pherall.com` |
| `NEXT_PUBLIC_APP_URL` | **Yes** | Same as above — used in emails and JSON-LD |
| `ADMIN_EMAIL` | **Yes** | Email address of the admin account |
| `ADMIN_PASSWORD` | **Yes** | Password for the admin account (hashed on first seed) |
| `RESEND_API_KEY` | Recommended | Resend API key for transactional email |
| `EMAIL_FROM` | Recommended | Sender address, e.g. `Pherall <noreply@pherall.com>` |
| `BUSINESS_EMAIL` | Recommended | Business contact email for admin notifications |
| `STRIPE_SECRET_KEY` | When using payments | Stripe secret key (`sk_live_…`) |
| `STRIPE_PUBLISHABLE_KEY` | When using payments | Stripe publishable key (`pk_live_…`) |
| `STRIPE_WEBHOOK_SECRET` | When using payments | Stripe webhook signing secret (`whsec_…`) |

> **Note:** `CRON_SECRET` is automatically generated by Vercel and injected into your deployment — you do not need to set it manually.

> **Stripe alternative:** All Stripe keys can also be configured via the admin dashboard after deployment at **Admin → Settings → Payments**, without requiring environment variables.

> **Email alternative:** Resend API key and sender address can be configured via the admin dashboard after deployment at **Admin → Settings → Notifications**.

## 2. Database Setup

### First deployment

Run the database migrations against your production database before or immediately after your first deployment:

```bash
DATABASE_URL="your-production-connection-string" npm run db:migrate:deploy
```

Then seed the admin account and default business settings:

```bash
DATABASE_URL="your-production-connection-string" ADMIN_EMAIL="admin@yourdomain.com" ADMIN_PASSWORD="your-secure-password" npm run db:seed
```

### Subsequent deployments

Vercel runs `npm install` then `npm run build`. The `postinstall` script runs `prisma generate` automatically before the build, so the Prisma client is always up to date.

When you push new Prisma migrations, run `db:migrate:deploy` against production before or after deployment (migrations are backward-compatible by convention — run after deploy if safe, before if the new code requires the migration).

## 3. Vercel Cron Job

The file `vercel.json` configures a cron job that fires the appointment reminder endpoint every hour:

```json
{
  "crons": [
    {
      "path": "/api/cron/send-reminders",
      "schedule": "0 * * * *"
    }
  ]
}
```

Vercel automatically:
1. Generates a `CRON_SECRET` environment variable for your deployment
2. Sends `Authorization: Bearer ${CRON_SECRET}` when invoking the cron path

No manual configuration is required for the cron secret. The endpoint will reject any request without the correct secret.

> **Note:** Cron jobs on Vercel require a Pro plan or higher.

## 4. Stripe Setup

### When you're ready to accept payments

1. Create a Stripe account at stripe.com
2. Go to the Stripe dashboard → **Developers → API keys**
3. Copy your **Publishable key** and **Secret key**
4. Go to **Developers → Webhooks → Add endpoint**
   - URL: `https://yourdomain.com/api/webhooks/stripe`
   - Events to listen for:
     - `checkout.session.completed`
     - `payment_intent.payment_failed`
     - `charge.refunded`
5. Copy the **Signing secret** from the webhook endpoint
6. Enter these three keys in your Vercel environment variables **or** via **Admin → Settings → Payments**

### Stripe test mode

Use `sk_test_…` and `pk_test_…` keys in your staging environment to test payments without real money.

## 5. Email Setup (Resend)

1. Create an account at resend.com
2. Verify your domain (required to send from your own domain address)
3. Create an API key under **API Keys**
4. Add `RESEND_API_KEY` to Vercel environment variables **or** configure via **Admin → Settings → Notifications**
5. Set `EMAIL_FROM` to a verified sender, e.g. `Pherall <hello@pherall.com>`

Without email configured, all notification sends are skipped (logged to console as `[email] No API key configured`). No errors are thrown — the app works fully without email, just silently.

## 6. Admin Account Setup

On first deployment, run the seed command (see §2). This creates:
- The admin user with the email and password from `ADMIN_EMAIL` / `ADMIN_PASSWORD`
- Default `BusinessSettings` record (edit via Admin → Settings → Business)
- Default `BookingSettings` record (edit via Admin → Settings → Booking)
- Empty policy documents (edit via Admin → Policies)
- Empty CMS sections (edit via Admin → Content)

> The admin password is hashed with bcrypt on seed. The plaintext password is never stored.

After your first login, change the admin password via **Admin → Settings → Account**.

## 7. Final Launch Checklist

Before going live, verify:

- [ ] `DATABASE_URL` points to production database
- [ ] `AUTH_SECRET` is set (unique random value, not reused from dev)
- [ ] `NEXTAUTH_URL` is set to the production domain
- [ ] `NEXT_PUBLIC_APP_URL` is set to the production domain
- [ ] `ADMIN_EMAIL` and `ADMIN_PASSWORD` are set (seed will fail without them)
- [ ] Database migrations have been applied (`db:migrate:deploy`)
- [ ] Database has been seeded (admin account exists)
- [ ] Admin login works at `/admin/login`
- [ ] At least one Service is created and set to active
- [ ] Business name, timezone, and contact details are configured in Admin → Settings → Business
- [ ] Booking settings (hours, policies) are configured in Admin → Settings → Booking
- [ ] Availability schedule is set in Admin → Availability
- [ ] Policies are written and published in Admin → Policies
- [ ] Homepage content is configured in Admin → Content → Homepage
- [ ] Email is configured (Resend API key) and a test booking sends successfully
- [ ] Stripe is configured if accepting payments (test with a test card first)
- [ ] Domain DNS is pointing to Vercel
- [ ] SSL certificate is issued (Vercel handles this automatically)
- [ ] `robots.txt` is accessible at `/robots.txt`
- [ ] `sitemap.xml` is accessible at `/sitemap.xml`

---

## 8. Monitoring

- **Application logs:** Vercel dashboard → Functions tab
- **Email delivery:** Admin → Settings → Notifications (notification log is stored in the database)
- **Cron execution:** Vercel dashboard → Cron Jobs tab (shows last run time and result)
- **Stripe payments:** Stripe dashboard → Payments

---

## 9. Upgrading

To apply new database migrations after a code update:

```bash
npm run db:migrate:deploy
```

The `prisma generate` step is automatic on every Vercel deployment via the `postinstall` script.
